# LightBench

> **Історичний стан ЛР3.** ELF `962ff5e43d9df2e390ab5515427a2136aa1a5a55673683e049c90bd9fd89931f`: S2 3606027 мс МК, 80 пар BUTTON/POINT, 64 записи RAM з CRC `7f04a102`; S3 80 пар, 304 експорти з коректним CRC та контрольована відмова I²C. Спостерігався `fault=flash`; FR-12 і повний CPU load не підтверджені. `make build` і `wokwi.toml` використовують `build-adc-independent`; перед відтворенням звіряйте ELF за хешем. Наведені нижче історичні результати належать своїм збіркам.


Пашко Максим Ігорович, ІО-32.

LightBench порівнює світло та положення носія у вибраних оператором точках. LDR дає raw ADC, MPU6050 дає кут від вектора тяжіння, кнопка зберігає останню пару разом із часами обох джерел і причинами непридатності. Потоки збираються незалежно раз на 20 мс. Серія має окремі статистики, RAM-журнал на 64 точки та CSV-експорт зі сталого знімка.

## Кандидат UART, 01.11.2026

TX ставить сформований рядок цілком або відхиляє його; HAL передає послідовні фрагменти кільця без очікування в основному циклі. Host-тести включають заповнення, обертання кільця, відмову запуску HAL та відновлення. Короткі Wokwi-випробування ELF SHA-256 `ccacdff46ba36c49f6f21eaf6e56eef459f642783cdae29063a9bf075659f1e4`: S1 66,002 с, S3 80/80 точок, 303 завершені CSV з коректним CRC. Максимум затримки від входу 37,670 мс; за навантаження IMU мав перерву 1,020 с і flash повернула помилку. UART sweep дав 84 у лічильнику tx_lost; це лічильник відхилення повідомлення або помилки запуску HAL, не кількість втрачених байтів. S2 цього ELF підтверджено: 3606082 мс часу MCU, 80 фактичних точок, кінцевий експорт 64 записів із перевіреним CRC. Дані нижче стосуються відповідних попередніх збірок.

## Кандидат нового I²C/MPU шару, 01.11.2026

У поточній гілці MPU6050 має окремий інтерфейс регістрових запитів, перевірку записаної конфігурації та атомарне оновлення виміру. Новий автомат I²C1 використовує незмінену HAL-ініціалізацію та власний обмежений обмін через регістри. Для Wokwi додано захисний інтервал 100 мкс після адреси й кожного переданого байта; підтвердження RXNE/STOPF та загальний deadline 10 мс залишаються обов'язковими. Попередній транспорт вилучено, vendor HAL збережено.

Шість host-наборів з ASan/UBSan та ARM-збірка пройшли. VCD підтвердив ACK записів живлення/конфігурації і readback. Тестова I²C-модель перевірила NACK до 2 с та SDA LOW на 10–13 с із відновленням. S1 охопив 65,988 с і 3299 опитувань кожного каналу. S3 дав 80/80 точок, максимальну затримку від GPIO входу 48,089 мс; 182 експорти пройшли CRC. Під навантаженням зафіксовано недоступність IMU, пропуски ADC, помилку flash і втрати TX; ці обмеження збережено в результатах. ELF SHA-256: `572c6a6af1869a1553e3214909ffc0690bc254f5a07cfdd4ba1117c993c4fc38`, flash 27628/28672, RAM із резервами 10096/12288 байтів.

Цей розділ описує попередній ELF `572c…`, а не виміряний UART-кандидат вище. Дані різних збірок не об’єднуються. Поточні конфігурація Wokwi і `make build` використовують `firmware/build-uart-independent`; докази та обмеження поточної збірки наведено в [baseline ЛР4](docs/baseline-lab4.md).

## Запуск

Потрібні Docker, Make, Python 3, VS Code із Wokwi та чинною ліцензією. Контейнер Ubuntu 24.04 містить ARM GCC 13.2.1. Пакети компілятора та базовий образ зафіксовано в Dockerfile.

```sh
make build
make test
make test-linux
make sanitize
make coverage
```

У VS Code відкрийте цей корінь і виконайте `Wokwi: Start Simulator`. Файли прошивки задано у `wokwi.toml`; монтаж у `diagram.json`. Це STM32 HAL, Cortex-M0+, без Arduino. Базовий CubeMX `.ioc` описує Core; додаткові ADC/GPIO та IRQ UART налаштовано у `Platform/board.c`.

UART 115200 8N1: `selftest`, `status`, `run`, `stop`, `export`, `imuaddr 0x68`, `imuaddr 0x69`. Після `run` натисніть кнопку Reference point або M. LED світиться в активній серії. `stop` друкує статистики, `export` передає CSV, count, overwritten і CRC32. Повторний `export` під час передачі дає busy. Адреса 0x69 без зміни AD0 створює контрольний NACK.

Світло зберігається як raw 0..4095, не калібровані люкси. Кут 0..180° придатний лише за норми прискорення 0.85..1.15 g. Для пари вік кожного джерела має бути ≤40 мс, розрив між джерелами ≤20 мс. Відхилені пари також зберігаються. Часи є uptime у мс, не календарем.

## ЛР3: історія підготовки, 28.10.2026

Додано журнал внутрішньої flash із CRC/commit, відновлення 64 останніх підтверджених точок, TIM3 1 МГц, метрики задач і циклу, missed releases та stack painting. Дві чисті ARM-збірки 28.10.2026 ідентичні: flash 27732/28672, RAM 10112/12288 байтів із резервами. П'ять C-наборів, три Python-тести й ASan/UBSan пройшли на macOS/Linux. [Факти й хеші](docs/metrics/lab3/verification.json), [задачі](docs/tasks.md), [сценарії](docs/baseline-lab4.md), [межі](docs/limitations.md).

Наведений вище абзац стосується старої збірки. Поточна версія використовує SysTick; її S1–S3 наведено на початку README. Flash у моделі повернула fault, відновлення після reset і втрати живлення не перевірено. `point` означає запис у RAM, а підтвердження flash потребує успішного readback.

## Перевірений baseline ЛР2

Дві чисті збірки дали ідентичні ELF/HEX/BIN. Код займає 23936 байтів flash із доступних 28672; RAM за linker map 8456 із 12288 байтів, включно з резервами heap/stack. Чотири C-набори й три Python-тести пройшли на macOS та Linux, ASan/UBSan пройшли. Coverage App+Devices: 100% рядків, 96.92% гілок. Board/HAL до цієї метрики не входять.

Власна симуляція 27.10.2026 тривала 29.258 с модельного часу з паузами для зміни входів. Отримано 75 точок; обидва 64-рядкові експорти незалежно перевірено за CRC. Перевірено перезапис кільця, точку під час експорту, NACK і відновлення IMU без зупинки ADC. Медіани періодів ADC/IMU становлять 19.997/19.994 мс. Власні VCD/SR/PVS, UART, хеші та результати PulseView наведені в документації.

У ЛР3 додано код запису у flash та метрики. У моделі Wokwi S2 тривав понад годину, S3 перевіряв події під час експорту. Запис у flash завершився помилкою, тому збереження після reset не підтверджено. Деталі й обмеження наведено у [звіті ЛР3](docs/lab3/Лабораторна_робота_3_Максим_Пашко_ІО-32.pdf) та [записах](docs/captures/lab3/README.md).

Core/HAL/CMSIS та ліцензії збережено з дозволеної основи. [Походження коду](docs/boilerplate-readme.md).
