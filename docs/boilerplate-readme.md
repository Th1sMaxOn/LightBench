# Походження основи

Core, HAL/CMSIS, startup та базова конфігурація походять із дозволеного SP-Boilerplate та [wokwi/stm32-hello-wokwi](https://github.com/wokwi/stm32-hello-wokwi). Ліцензії залежностей збережені в репозиторії. [Vendor manifest](vendor-manifest.json) фіксує точні хеші Drivers.

У попередньому MPU/I²C шарі знайдено суттєві збіги з іншими локальними роботами; походження цих власних фрагментів не встановлено. Вони не входять до дозволеного стартового шаблону.

Кандидат від 01.11.2026 замінює MPU6050 та власний низькорівневий I²C транспорт. Драйвер використовує карту регістрів виробника (MPU-6000/MPU-6050 Register Map and Descriptions, revision 4.0): перевіряє ідентифікатор і readback конфігурації, читає пакет виміру в тимчасовий буфер. HAL налаштовує периферію; власний автомат виконує адресну, TX, STOP, turnaround та RX стадії з одним deadline. Початкові HAL-запуски завершувалися помилкою; після введення захисних інтервалів для моделі VCD підтвердили запис і readback. Незмінні адреси, регістри та коефіцієнти MPU6050 визначені виробником і не потребують штучного розрізнення між роботами.

App/bench, pose, records, protocol та відповідні тести описують LightBench. Спільна vendor-основа не є прикладною логікою продукту. Схема містить LDR, IMU, кнопку й окремі діагностичні маркери.

TX-кандидат реалізовано окремо для інтерфейсу LightBench: прийняття цілого повідомлення, одноосібний виробник і передача фрагментів через штатний HAL. Перевірки HAL-моделі наведено в test_serial_tx; окреме коротке випробування Wokwi показало коректні CRC завершених експортів і втрати відповідей UART при навантаженні. Аналіз покриття використовує JSON-формат GCC gcov із Docker-образу; захоплення RFC2217 використовує pySerial 3.5 (BSD), зафіксований у requirements-capture.txt.
