# LightBench

Пашко Максим Ігорович, ІО-32.

LightBench порівнює світло та положення носія у вибраних оператором точках. LDR дає raw ADC, MPU6050 дає кут від вектора тяжіння, кнопка зберігає останню пару разом із часами обох джерел і причинами непридатності. Потоки збираються незалежно раз на 20 мс. Серія має окремі статистики, RAM-журнал на 64 точки та CSV-експорт зі сталого знімка.

## Запуск

Потрібні Docker, Make, Python 3, VS Code із Wokwi та чинною ліцензією. Контейнер Ubuntu 24.04 містить ARM GCC 13.2.1. Пакети компілятора та базовий образ зафіксовано в Dockerfile.

```sh
make build
make test
make test-linux
make sanitize
make coverage
```

У VS Code відкрийте цей корінь і виконайте `Wokwi: Start Simulator`. Файли прошивки задано у `wokwi.toml`; монтаж у `diagram.json`. Це STM32 HAL, Cortex-M0+, без Arduino. Базовий CubeMX `.ioc` описує Core; додаткові ADC/GPIO та IRQ UART налаштовано у `Platform/board.c`.

UART 115200 8N1: `selftest`, `status`, `run`, `stop`, `export`, `imuaddr 0x68`, `imuaddr 0x69`. Після `run` натисніть кнопку Reference point або M. LED світиться в активній серії. `stop` друкує статистики, `export` передає CSV, count, overwritten і CRC32. Повторний `export` під час передачі дає busy. Адреса 0x69 без зміни AD0 створює контрольний NACK.

Світло зберігається як raw 0..4095, не калібровані люкси. Кут 0..180° придатний лише за норми прискорення 0.85..1.15 g. Для пари вік кожного джерела має бути ≤40 мс, розрив між джерелами ≤20 мс. Відхилені пари також зберігаються. Часи є uptime у мс, не календарем.

## ЛР3: код і підготовлені вимірювання

Додано журнал внутрішньої flash із CRC/commit, відновлення 64 останніх підтверджених точок, TIM3 1 МГц, метрики задач і циклу, missed releases та stack painting. Дві чисті ARM-збірки 28.10.2026 ідентичні: flash 27732/28672, RAM 10112/12288 байтів із резервами. П'ять C-наборів, три Python-тести й ASan/UBSan пройшли на macOS/Linux. [Факти й хеші](docs/metrics/lab3/verification.json), [задачі](docs/tasks.md), [сценарії](docs/baseline-lab4.md), [межі](docs/limitations.md).

Нова прошивка ще не запущена на MCU/Wokwi. Підтримка TIM3 і внутрішньої flash моделлю, S1–S3, годинний S2, runtime stack/heap, reset та обрив живлення не підтверджені. ЛР3 не завершено. Команди `metrics`, `metrics reset`, `period 20/10/5/2/1` підготовлено для дослідів. `point` означає запис у RAM, `persist` після readback означає підтвердження flash. Незаписана черга може зникнути після reset.

## Перевірений baseline ЛР2

Дві чисті збірки дали ідентичні ELF/HEX/BIN. Код займає 23936 байтів flash із доступних 28672; RAM за linker map 8456 із 12288 байтів, включно з резервами heap/stack. Чотири C-набори й три Python-тести пройшли на macOS та Linux, ASan/UBSan пройшли. Coverage App+Devices: 100% рядків, 96.92% гілок. Board/HAL до цієї метрики не входять.

Власна симуляція 27.10.2026 тривала 29.258 с модельного часу з паузами для зміни входів. Отримано 75 точок; обидва 64-рядкові експорти незалежно перевірено за CRC. Перевірено перезапис кільця, точку під час експорту, NACK і відновлення IMU без зупинки ADC. Медіани періодів ADC/IMU становлять 19.997/19.994 мс. Власні VCD/SR/PVS, UART, хеші та результати PulseView наведені в документації.

У ЛР3 додано код запису у flash та метрики. У моделі Wokwi S2 тривав понад годину, S3 перевіряв події під час експорту. Запис у flash завершився помилкою, тому збереження після reset не підтверджено; фізичні виміри живлення не проводилися. Деталі й обмеження наведено у [звіті ЛР3](docs/lab3/Лабораторна_робота_3_Максим_Пашко_ІО-32.pdf) та [записах](docs/captures/lab3/README.md).

Core/HAL/CMSIS та ліцензії збережено з дозволеної основи. [Походження коду](docs/boilerplate-readme.md).
