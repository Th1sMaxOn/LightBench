# Коротка діагностика внутрішньої flash

Використано окрему діагностичну збірку поточного коду, `LAB3_DIAGNOSTIC=1`, ELF SHA-256 `d3cadfd5aac96399828199781cb3ca9a36acf6776dc320f4eee60e95ca909f56`. Це інша збірка, не ELF годинного S2; її метрики часу не переносяться до S1–S3. Сирий UART, налаштування стенду, VCD, повний GDB readback і CPU RAM snapshot збережено поруч.

Після точки seq=1 драйвер намагався стерти сторінку 14 за адресою 0x08007000. CPU snapshot: unlock=HAL_OK, erase=HAL_OK, PageError=FFFFFFFF, HAL error=0, lock=HAL_ERROR, SR/CR перед і після=0. CPU зчитав 512 слів сторінки після erase: усі 512 дорівнювали нулю, а не FFFFFFFF; незалежне читання GDB показало всі нулі в обох сторінках 0x08007000 і 0x08007800. UART повідомив fault, committed=0. Вбудована перевірка erase відхилила некоректний результат. Результат відтворює попередній окремий діагностичний запуск.

Це конкретна межа використовуваної Wokwi-моделі C031: HAL_OK не відповідає readback. Причину на рівні внутрішньої реалізації симулятора або реального контролера не встановлено. Доказу роботи persist, перевірки reset з даними або фізичної втрати живлення тут немає. Перевірку перерваного flash-запису в цій конфігурації виконати неможливо, поки erase не створює стерту сторінку; для перевірки потрібна працездатна модель фізичного носія або реальна плата. RAM-буфер не замінює flash.
