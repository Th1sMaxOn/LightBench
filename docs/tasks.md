# Задачі LightBench у ЛР3

**Актуалізація.** 30.10.2026: актуальний час планування --- SysTick 1 мс, а не TIM3; S1/S2/S3, NACK та sweep виконані. Flash у моделі повернула fault; відновлення після reset не підтверджено. Докладні результати в docs/lab3-report.md та Lab03/Work/systick-20261029. Попередні фрази про очікування дослідів є історичними.

Одна прошивка, один стек MSP, виклики runtime_poll у нескінченному циклі. RTOS немає. Номінальна частота ядра 48 МГц. Періоди задаються uptime від TIM3; пропущені випуски пропускаються з лічильником, без нескінченного catch-up.

| Задача | FR | Період / подія | Дедлайн і межа |
|---|---|---|---|
| ADC | 02,03,07,11 | 20 мс | Завершення до наступних 20 мс; gap >40 мс; HAL timeout 2 мс, окрема повторна ініціалізація |
| IMU + геометрія | 02,04,07,11 | 20 мс за ready | До наступних 20 мс; спільний deadline I²C 10 мс; вектор 0.85..1.15 g |
| IMU probe | 01,11 | Раз на 1000 мс за fault | Без частіших повторів; синхронна перевірка WHO_AM_I та конфігурації |
| Кнопка | 06,07,09 | Кожен прохід; стабільність HIGH/LOW 30 мс | Одна точка до 50 мс після підтвердження; вік джерел ≤40 мс, skew ≤20 мс |
| UART parser | 05,08,10,13 | RX ISR, до 64 байтів за прохід | status ≤100 мс без попередньої черги TX; довгий/некоректний рядок відхиляється |
| Snapshot/export | 09,10 | export, потім один рядок за прохід | Знімок 64×28 байт; інкрементний CRC; починати рядок при TX free ≥768 |
| Постійна точка | 12 | RAM-черга на 8 точок | Один erase АБО один doubleword за прохід; persist лише після readback останнього commit |
| Стан/LED | 01,14 | LED кожен прохід; status раз на 1000 мс | LED відображає серію; окремі ADC/IMU/RX/TX/store помилки |
| Metrics | методика | metrics / metrics reset | По одному рядку за прохід, task n/min/avg/max, intervals, missed, stack, heap |

Сховище: 0x08007000..0x08007fff, дві сторінки по 2048 байтів. Формат 32 байти, little endian: sequence, series, mark_ms, light_ms, pose_ms, raw, angle_cdeg, flags, commit 0xb34c, CRC32 вихідної 28-байтової точки з reserved=0. Останні 8 байтів записуються останніми. Після ротації інша сторінка зберігає 64 підтверджені точки. Незавершені RAM-черга/статистики серії не відновлюються. Часи до reset є uptime попереднього запуску.

PointStore не залежить від HAL. internal_flash використовує справжні HAL_FLASHEx_Erase та HAL_FLASH_Program, без HAL_Delay. Фактична підтримка в Wokwi ще потребує запуску. Якщо erase/program/readback не працюють, store.failed=1 і нове підтвердження persist не з'являється. RAM-логер продовжує роботу.

ISR: SysTick для HAL та часу планування; USART2 для кілець RX 256 і TX 2048. ISR не модифікує серію чи історію точок.

Кандидат після невдалого TIM3-пілота використовує SysTick з кроком 1 мс. Усі поля us — масштабовані мілісекунди, не вимірювання з мікросекундною роздільністю; uint32 us придатний для різниць <71.58 хв. Flash stall може об'єднати кілька SysTick-переривань, тому годинний uptime необхідно звіряти з незалежним VCD. Реальний blackout flash потребує виміру на платі.

period 20/10/5/2/1 змінює обидва періоди для пошуку межі. Це діагностичні режими; базові FR оцінюються за period 20. Зміна періоду після виміру не змінює початкову вимогу.
